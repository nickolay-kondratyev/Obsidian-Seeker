READ FIRST: the plan ticket (search `_tickets/` for "PLAN: PP-OCRv6-tiny default OCR engine") — D3, D8, D9, D10, D11. Then `src/ocr-model-catalogue.ts` (ticket 2: `OcrModelSetting`, `OCR_MODEL_PRESETS`, `resolveOcrModel`, `presetMatching`, `hfResolveUrl`, `ocrModelIdentity`, `DEFAULT_OCR_MODEL`), `src/ocr-paddle-runner.ts` (the runner a validation instantiates as a THROWAWAY), `src/model-validate.ts` + `src/model-validate.test.ts` + `src/model-candidate.ts` (`isValidHfSlug`, `revisionInfoUrl`, `parseRevisionSha`, `describeModelLoadError`) and `src/main.ts` `switchModel` / `resolveRevisionSha` — the embedding-model validate-then-switch you mirror; `src/main.ts` `refreshOcrEngine` + `ocrModelSetting(settings)` accessor (ticket 3); `src/settings-tab.ts` `renderImageOcrAdvanced` (ticket 4: add the picker ABOVE the fallback-languages field); `src/types.ts` `SeekerSettings`/`DEFAULT_SETTINGS`.

## Goal
Let the user pick the PP-OCR model (Tiny / Small / Medium / Custom HF repo) with a validate-then-save flow, explicitly persisted even for the default, stamped on every record, WITHOUT dropping or re-OCRing existing records.

## Deliverables
1. `src/types.ts`: `ocrModel: OcrModelSetting` in `SeekerSettings`, default `DEFAULT_OCR_MODEL` = `{ kind: 'preset', preset: 'tiny' }` (explicit, D8; new key, `Object.assign` backfills — no migration). Point ticket 3's `ocrModelSetting(settings)` accessor at it.
2. `src/ocr-model-validate.ts` (Obsidian-free, `src/ocr-model-validate.test.ts` with stubs): `validateOcrModel(candidate: OcrModelSetting, deps: { resolveRevisionSha(repo, revision|null): Promise<string|null>; fetchHead(url): Promise<{ ok: boolean; status: number }>; makeRunner(spec): Pick<PaddleOcrIframeRunner,'ocr'|'teardown'>; probeImage: ArrayBuffer })`: Promise<{ ok: true; setting: OcrModelSetting /* custom with the PINNED sha */; ep: string } | { ok: false; error: string }>`. Steps: preset → resolve through the catalogue (still probe-load it: a preset the user never used must download + work before it becomes active); custom → `isValidHfSlug(repo)`, non-empty paths, `resolveRevisionSha` (blank revision = main → sha; a 40-hex revision is used as-is), HEAD each of the three URLs (must be `ok`; nothing more — HF `resolve` URLs 302 to an LFS CDN and `fetch` follows redirects, so size/content-type headers are unreliable and the probe OCR below is the real proof), then `makeRunner(spec).ocr(probeImage)` must return `error: null` and text containing every probe word (case-insensitive, whitespace-normalised); ALWAYS `teardown()` the throwaway. Plain-language errors (reuse/extend `describeModelLoadError`): bad slug, revision not found, file missing (name which), model failed to load, probe text mismatch (show what it read).
3. Probe image: `src/ocr-probe-image.ts` exporting `OCR_PROBE_WORDS = ['seeker','ocr','probe']`-style words and `OCR_PROBE_PNG_BASE64` (a ~2–4 KB PNG rendered ONCE with `scripts/ocr-fixtures.mjs`-style Playwright rendering of large clear text; commit the base64 constant, not a binary; note the generation recipe in the file header). Unit test: decodes to a PNG signature.
4. `src/main.ts`: `switchOcrModel(next: OcrModelSetting): Promise<{ ok: true } | { ok: false; error: string }>` — desktop-only (Notice on mobile like `switchModel`), refuses while a reindex runs, runs `validateOcrModel` with the real deps (`resolveRevisionSha` already exists; `fetchHead` = `fetch(url, { method: 'HEAD' })`; `makeRunner` = `new PaddleOcrIframeRunner(spec, { iframeId: 'seeker-ocr-paddle-probe-iframe' })` — its OWN iframe id (plan §Shared conventions): the live runner's iframe may exist and the runners remove-by-id; the throwaway never evicts caches), on success persists `settings.ocrModel`, tears down the live engine and `refreshOcrEngine()` (identity key changes → re-wire; its parent-side `evictStaleOcrModelCaches` call drops the previous model's bytes), clears any fallback reason, Notice: "Seeker: OCR model switched to <label>. Images already read keep their text; use Rebuild OCR cache to re-read everything with the new model." (D10 — NO clear, NO automatic re-OCR). Because validation already downloaded the files into the shared Cache API, the live runner's first load after the switch is warm.
5. `src/settings-tab.ts` `renderImageOcrAdvanced`: ABOVE the fallback languages: "OCR model" row with a dropdown Tiny (default, ~6 MB) / Small (~30 MB, full dictionary) / Medium (~139 MB, best accuracy) / Custom, showing the CURRENT setting (`presetMatching` for a custom equal to a preset). Choosing a preset ≠ current → immediately runs `switchOcrModel({ kind: 'preset', preset })` with a spinner + inline result (validation downloads it). Choosing Custom reveals five text fields prefilled from the current resolved spec: HF repo, revision (placeholder "main — pinned to a commit on validate"), detection path, recognition path, dictionary path; a "Validate & switch" CTA button runs `switchOcrModel({ kind: 'custom', ... })`; failure renders the error under the fields and keeps the input; success re-renders showing the pinned sha (short) on a faint line. A "Re-OCR all images now" hint next to the success state is just the existing Rebuild button one row up — link the copy, do not add a third button. Mobile: fields read-only with the same copy `switchModel` uses.
6. Records: already stamped via `engine.model` (ticket 2/3). Add to the OCR status line a faint "Model: <label> · <repo>@<sha7>" so the active model is visible without opening the disclosure (D8 "be explicit").

## Acceptance
- `npm run typecheck`, `npm run test`, `npm run build` green; `ocr-model-validate.test.ts` covers: preset OK, bad slug, missing file, probe mismatch, revision pinning, throwaway teardown on failure.
- Manual (record in the resolution): switch Tiny→Small in a dev vault (download, validation OCR, Notice, records untouched, new images stamped `model: small@...`); a bogus custom repo → inline error, nothing saved; a bogus path → "file missing" naming the path.
