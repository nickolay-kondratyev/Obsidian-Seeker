# Plan: retrieval-quality e2e suite on the real embedding stack (container-runnable)

Planning ticket nid_w9o911oolzzh9ytbi6tob3sek_e (interview rounds 1-2 with the human, 2026-09-03). This ticket is the high-level plan; the three implementation tickets depend on it and on each other in order.

## Goal
`npm run test:e2e` indexes a frozen ~150-note markdown corpus through the REAL production stack (LocalEmbedder -> transformers.js in Chromium, SearchOrchestrator, IndexStore on real IndexedDB), runs real queries, and fails when ranking quality regresses. Runs headless inside the dev container in ~1 minute (wasm, ~4 chunks/s). Ground truth comes from BEIR CQADupstack-android (StackExchange duplicate-question pairs). It is an integration test by strict definition; "e2e" names the slow real-model gate and a future real-Obsidian suite can join it.

## Decisions (HUMAN-confirmed; do not re-litigate)
- Build on the existing bench harness (bench/harness/run.mjs, bench/harness/page.ts, bench/harness/esbuild.mjs): same Chromium resolution (/usr/bin/chromium in container, Playwright's bundled build on host after `npm run bench:setup`), same persistent profile .bench-cache/ (shared 100 MB model download), same page origin/port. bench and e2e therefore cannot run concurrently.
- Separate `npm run test:e2e`; NOT part of `npm test` (vitest file gated on E2E=1, precedent bench/harness/webgpu-software.test.ts gated on BENCH=1).
- Dataset: BEIR CQADupstack-android, fetched from the public plain-JSONL mirror https://huggingface.co/datasets/mteb/cqadupstack-android (corpus.jsonl 14.6 MB / 22,998 docs; queries.jsonl 699 queries; qrels/test.tsv 1,696 rows, header `query-id<TAB>corpus-id<TAB>score`). WHY-NOT the BEIR zip: cqadupstack.zip is 5.3 GB. WHY-NOT SciFact: CC BY-NC-SA; CQADupstack content is CC BY-SA (StackExchange), no non-commercial clause.
- Subset is COMMITTED and FROZEN (like bench/corpus): seeded-random 30 test queries, ALL their relevant docs, seeded-random distractors up to ~150 docs total, generated by a committed script. Frozen means: changing it re-pins the baseline.
- One corpus, one index pass (1-min budget rules out a second bench/corpus pass). Obsidian query syntax stays covered by src/query-parser.test.ts.
- Notes: one markdown file per doc, `# <title>` + body. No invented frontmatter/tags.
- Assertions (gated on the shipped hybrid ranking only): (1) aggregate nDCG@10 and Recall@10 over the 30 queries >= pinned baseline - 0.02 tolerance; (2) ~10 hand-curated must-pass queries tagged keyword|semantic with a rank bound. Dense-only (denseWeight=1) and bm25-only (denseWeight=0) metrics are REPORTED, opt-in via E2E_CHANNELS=1 (each channel re-embeds every query, ~8 s/channel on wasm), never gated.
- Runs locally/agent-side and as a release gate in release.sh (verify_basics). No CI job now (follow-up once stable).

## Tickets (in dependency order)
1. Dataset generator + committed subset + pin test.
2. e2e harness (search entry on page.ts, e2e/harness/run.mjs, metrics, aggregate gate, baseline pin, npm script, docs).
3. Curated keyword/semantic queries + release.sh gate + CLAUDE.md pointers.

## Key facts for implementers
- Container throughput ~4 chunks/s wasm, model cold start ~1.1 s warm-cache (docs/perf-bench.md). Query embedding ~0.25 s each on wasm.
- SearchOrchestrator.search(query, topK=10, recencyOverride?) -> { results: ScoredChunk[], entry } in src/search.ts (~L3308). ScoredChunk has path, score, ranking_signals {dense, bm25, hybrid, denseRaw, ...} (src/types.ts ~L708). Fusion: hybrid = alpha*dense + (1-alpha)*bm25, alpha = settings.denseWeight (src/fusion.ts hybridFusion; DEFAULT_SETTINGS.denseWeight = 0.85).
- Result path -> doc id: the note file name is `<corpus-id>.md`, so doc id = basename without extension; dedupe chunks by note path before computing ranks (a note may yield several chunks).
