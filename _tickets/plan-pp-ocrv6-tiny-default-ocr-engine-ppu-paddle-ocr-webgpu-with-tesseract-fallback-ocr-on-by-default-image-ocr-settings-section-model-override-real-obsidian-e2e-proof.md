High-level PLAN (ratified with the human 2026-09-03 in two interview rounds, see notes on nid_ybv5cljnxx9wb4ha2gbvpsbmd_e). This ticket is CLOSED; it is the plan of record the numbered implementation tickets depend on. Read it first when picking up any of them.

## Goal
Make PP-OCRv6-tiny (via the `ppu-paddle-ocr/web` wrapper, onnxruntime-web, WebGPU when present) the DEFAULT OCR engine behind the existing `OcrEngine` interface (`src/ocr-cache.ts`), keep tesseract.js (`src/ocr-iframe-runner.ts`) as the FALLBACK with a visible warning, turn image OCR ON by default (opt-out), give OCR its own settings section with a model override, and prove the engine runs in real Obsidian with an e2e test.

Background reading: `docs/research/image-ocr.md` (§5 runtime placement, §8a/§8d engine survey, §11 this follow-up, §12 D2/D8, §13 tesseract baseline numbers). Existing code to mirror: `src/ocr-iframe-runner.ts` (iframe runner + child script pattern), `src/search.ts` `ocrPrepass` (the ONE engine call site; stamps `engine`/`v`/`langs` from the engine object AFTER each `ocr()` resolves), `src/main.ts` `refreshOcrEngine` / `onOcrSettingsChanged`, `src/settings-tab.ts` `renderOcr` (today inside Index → Advanced), `src/types.ts` `DEFAULT_SETTINGS` + `migrateSettings` (rev pattern), `src/model-validate.ts` + `src/model-candidate.ts` (validate-then-switch precedent for a HF model override).

## Facts (verified 2026-09-03)
- `ppu-paddle-ocr` 6.4.3, MIT, published 2026-08-27, one maintainer, repo active. Web entry `ppu-paddle-ocr/web`: no OpenCV, bare-imports `onnxruntime-web` (peer ^1.23) + `ppu-ocv/canvas-web`. jsdelivr bundle `https://cdn.jsdelivr.net/npm/ppu-paddle-ocr@6.4.3/web/+esm` resolves (42 KB) and rewrites deps to `/npm/onnxruntime-web@1.29.0/+esm` and `/npm/ppu-ocv@4.0.0/canvas-web/+esm`; ORT wasm binaries default to `https://cdn.jsdelivr.net/npm/onnxruntime-web@1.29.0/dist/`.
- The web build has NO internal worker: on the iframe main thread wasm inference blocks the Obsidian renderer. README: "the web build runs unchanged inside a Web Worker" (OffscreenCanvas only). WebGPU auto-selected (`["webgpu","wasm"]`) when `navigator.gpu.requestAdapter()` succeeds, silent wasm fallback. COOP/COEP only affects wasm multithreading (a srcdoc iframe cannot set it → single-thread wasm fallback is accepted).
- Models (Apache-2.0): HF repo `snowfluke/ppu-paddle-ocr-models`, pinned commit `bf1d5edb0335d3262be7caf13f766ba274b4cadd`, files `detection/ort/PP-OCRv6_tiny_det.ort` (1,882,568 B), `recognition/ort/PP-OCRv6_tiny_rec.ort` (4,530,048 B), `recognition/ppocrv6_tiny_dict.txt` (27,157 B). Also `PP-OCRv6_small_*` (~30 MB, full dictionary) and `PP-OCRv6_medium_*` (~139 MB) under the same layout; `ppocrv6_dict.txt` is the full dictionary. `resolve/<sha>/...` URLs answer with `access-control-allow-origin: *`.
- `ModelPathOptions` accept `ArrayBuffer` for detection/recognition/charactersDictionary → the plugin fetches + stores bytes in the Cache API itself. Per-line confidence is 0–1 (`recognition.minimumConfidence` default 0.5); `recognition.spaceRecovery` defaults false (CTC may drop inter-word spaces — must be evaluated); `detection.maxSideLength: "auto"` = clamp(0.75×longest, 960, 1920).
- The embedding model ALREADY loads from a third-party HF org (`onnx-community/...`, revision-pinned, `src/iframe-runner.ts`) → hosting the OCR model on upstream HF pinned to a sha is consistent; §11's "host it yourself" line is amended, a low-priority need-human ticket covers mirroring later.
- OCR has never shipped (tag 1.1.10 lacks all OCR code) → flipping OCR on is a plain settings migration.
- Container has no GPU (SwiftShader only); host WebGPU needs Chromium flags (see memory / `docs/perf-bench.md`); e2e headless Obsidian runs with `--disable-gpu`.

## Decisions (D-numbers referenced by the implementation tickets)
D1 Spike first, then gate. Extend `scripts/ocr-spike.mjs` with a `ppu-paddle-ocr` engine; results become §14 of `docs/research/image-ocr.md`. Gate: corpus mean word-accuracy ≥ tesseract's best (0.94 @2×) AND every CLEAN fixture ≥ 0.95 AND loads from jsdelivr in a non-sandboxed srcdoc iframe. Gate fails (or no load shape works) → a strong decision for the human: ticket tagged `decide,need-human` with the numbers/errors and the options; tickets 2–7 gain a dep on it; the agent does not choose the next candidate.
D2 Load shape: `+esm` bundle imported inside a Blob-URL `type: 'module'` Worker created by the OCR srcdoc iframe (no `sandbox` attribute — LOAD-BEARING, same as both existing iframes). Worker = never blocks the renderer; iframe = independent heap + teardown after the pre-pass drains. If the spike shows `+esm` bundling of ORT broken, fall back to vendoring the 42 KB wrapper bundle + ORT's own `dist/ort.webgpu.min.mjs` (spike decides).
D3 Models fetched by the plugin (inside the iframe's worker) into the Cache API `seeker-ocr-models`, keyed by the sha-pinned URL; bytes passed as `ArrayBuffer`s. Eviction of entries whose URL is not in the ACTIVE spec is PARENT-SIDE, orchestrated from `src/main.ts` (the same split as `src/model-registry.ts` `shouldEvictCacheUrl` + main.ts for the embedding model): a pure, unit-tested predicate plus a best-effort `evictStaleOcrModelCaches(keepUrls)` called by `refreshOcrEngine` when it builds the live runner. Eviction NEVER runs inside a runner's load — a throwaway validation runner (D9) must not evict the live model's bytes.
D4 `FallbackOcrEngine(primary, secondary, { onFallback })` implements `OcrEngine`; primary = PP-OCR runner, secondary = the existing tesseract runner. Switch for the REST of the pass on a primary LOAD failure or a TRANSIENT RPC failure (timeout/crash); deterministic per-image results never trigger it. Identity getters (`engine`/`version`/`langs`/`model`) delegate to the engine that produced the last result, so the prepass stamps correct provenance without changes. Both torn down at drain.
D5 Fallback warning: one `Notice` per pass at the switch, plus a PER-DEVICE persisted reason (localStorage, like the backend override in `src/platform.ts` — NOT data.json, which syncs across devices) rendering a warning row in the Image OCR section with a "Retry fast engine" button; cleared automatically the next time the primary loads (the PP-OCR runner's `onReady` callback, wired in main.ts, is the ONE clearing hook — the fallback engine has no ready hook of its own).
D6 OCR ON by default: `indexImages: true` in `DEFAULT_SETTINGS`, `settingsRev` 12 migration sets it `true` unconditionally for `fromRev < 12`; one-time desktop Notice on that migration. No download-consent prompt. The toggle is the opt-out.
D7 Settings: new top-level section "Image OCR" placed directly AFTER "Model & performance" (human: model first, OCR second). Contents: toggle, status line (cached count · MB, skipped svg/heic, live progress), fallback warning row (only when set), Clear OCR cache (always, two-step), Rebuild OCR cache (only while ON), then a disclosure "Advanced image OCR settings" that is collapsed on every open of the tab (tab-instance flag, never persisted). Disclosure contents: OCR model picker (D8) and "Fallback OCR languages (Tesseract)" (the existing `ocrLangs` field, relabeled). No threshold/pixel-cap knobs.
D8 Model override, EXPLICIT even for the default (human: record what was used, including tiny): persisted `ocrModel` is a discriminated union `{ kind: 'preset', preset: 'tiny' | 'small' | 'medium' } | { kind: 'custom', repo, revision /* 40-char sha, pinned at validate time */, detection, recognition, dictionary }`, default `{ kind: 'preset', preset: 'tiny' }`. Presets resolve through `src/ocr-model-catalogue.ts` (repo + sha + paths per tier) so a catalogue bump follows automatically for preset users. UI: picker Tiny/Small/Medium/Custom; Custom reveals the five fields prefilled with Tiny's values. HF-only.
D9 Validate-then-save for the override (mirrors `src/model-validate.ts`, Obsidian-free, stub-tested): slug check → resolve/pin sha → HEAD the three files → load in a THROWAWAY runner (its OWN iframe id, never the live runner's; never evicts) → OCR a committed probe PNG and require its words → persist → re-wire the live engine. Failure = one plain-language error, input preserved, nothing saved. Desktop-only.
D10 Switching the model NEVER drops or re-OCRs existing records (§12 D2; human: old records are still valid, just maybe not as good). The success Notice points at the easy re-OCR trigger in the same section ("Rebuild OCR cache" — clear + catch-up, §12 D8). Fallback (D4/D5) still applies under an override, the warning names the override.
D11 Provenance on records: `OcrEngine` gains `readonly model: string | null` (tesseract: null; PP-OCR: `<preset-or-custom>@<repo>@<sha7>`), `OcrRecord` gains optional `model?: string`, and PP-OCR results carry `ep: 'webgpu' | 'wasm'` via an optional `OcrResult.ep`. `ep` is the provider the wrapper SELECTED at load (`isWebGpuAvailable()` → webgpu, else wasm) unless the spike (§14) finds a signal ORT exposes for the provider actually USED — the spike records which it is, and the runner comment says so honestly. Additive fields; old records stay valid.
D12 Real-Obsidian e2e `e2e/ocr.e2e.ts`: vault = corpus + committed PNG fixture(s) with known text embedded from a note — the fixtures are OPT-IN in the harness (`ObsidianHarness.launch({ ocrFixtures: true })`), because every spec file launches its own Obsidian on a freshly assembled vault and `e2e/search.e2e.ts` asserts the exact "Indexed N files" count (images are committed as zero-chunk files and count, `src/search.ts` `imageZeroChunkCommit`); full reindex; search a phrase → the image (or its note) is a result; read the sidecar record `<vault>/.obsidian/plugins/seeker/index/ocr/<sha256>.json` and assert `engine === 'ppu-paddle-ocr'` (NOT the fallback) and log `ep`; env-gated `SEEKER_E2E_EXPECT_WEBGPU=1` asserts `ep === 'webgpu'` for host runs. Wired into `npm run test:e2e:obsidian` (thus `release.sh`).
D13 Tesseract runner stays as-is; shared iframe/RPC code is extracted only if the second runner would duplicate >~100 lines (decide in ticket 2).

## Shared conventions (every implementation ticket follows these)
- `OcrModelSetting` (the persisted discriminated union, D8), `DEFAULT_OCR_MODEL`, `OcrModelPreset`, `OCR_MODEL_PRESETS` and `resolveOcrModel` all live in `src/ocr-model-catalogue.ts`, a LEAF module (imports nothing from `src/types.ts`). `src/types.ts` imports the TYPE from it when ticket 5 adds the `ocrModel` field (types.ts already imports types from `./gpu-adapter`, so this direction is the established one). Nothing else defines these.
- Iframe ids: live PP-OCR runner `seeker-ocr-paddle-iframe`; throwaway validation runner `seeker-ocr-paddle-probe-iframe` (constructor option `iframeId`). Two runners must never share an id — for devtools legibility; correctness never depends on the id (runners remove the iframe by element reference and filter messages by `contentWindow`, exactly like `src/ocr-iframe-runner.ts` and `src/iframe-runner.ts`).
- Settings tab refresh: `src/main.ts` keeps NO handle to the settings tab; the tab re-reads plugin state on every `display()`/`rerender()`. Engine-side events (fallback set/cleared) never push to the UI.
- Any action that tears the live OCR engine down on demand (retry, model switch) uses `switchModel`'s guard first: refuse with a Notice while `isIndexing || orchestrator.isWriting()` (the OCR pre-pass runs inside the indexing pass).
- The ONE clearing hook for the per-device fallback warning is the PP-OCR runner's `onReady`; the one setting hook is `FallbackOcrEngine`'s `onFallback`.
- A less capable model implements these tickets: when a ticket and this plan disagree, the plan wins; when the plan and the code disagree, stop and open a `decide,need-human` ticket rather than improvising.
