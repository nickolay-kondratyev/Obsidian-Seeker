Model 2/6 (ticket nid_avq9wmbcrqb3k8c3clknc8gv5_e). src/sidecar.ts is now MODEL-FREE: dropped the ACTIVE_MODEL_SPEC import and the Q_BYTES/SIGN_BYTES/VEC_BYTES/RECORD_PAYLOAD_BYTES/DIM/MAX_VECTORS_PER_SHARD constants in favor of a pure `recordLayout(dim): RecordLayout`. `encodeRecord(t, layout)`, `decodeRecord(buf, off, layout)` and `isOffsetInRange(binSize, off, layout)` now slice by a passed layout. S_BYTES/CRC_BYTES/SHARD_CAP_BYTES stay constants. bulkAppend takes the active `dim` (from job.identity.dim in search.ts) and writes it into each jsonl line; decode paths (readRecordAt, sidecar-sync, and the byte-copy in compactDevice/coalesceSmallShards) key off the stored per-record `e.dim`, so the byte copy stays exact and needs no active-dim param. A wrong-width read now fails loud via the CRC/range guard instead of an explicit dim!=DIM assert. The dim-384 layout is byte-identical to the pre-refactor format (pinned by a frozen-hex test captured before the change); no SIDECAR_FORMAT bump, existing on-disk sidecars keep hydrating. Added codec round-trip tests for dims 256/768/1024/1000 and rewrote dim-consistency.test.ts around recordLayout.
