The e5/nomic families silently underperform without their 'query: '/'passage: ' (nomic: 'search_query: '/'search_document: ') prompts. Threaded the active model's prefixes through the embed path:

- `token-budget.ts`: `embedInput(c, docPrefix)` prepends docPrefix verbatim (no added separator; the user types the trailing space). `enforceTokenBudget(chunks, countTokens, docPrefix, budget=TOKEN_BUDGET)` — docPrefix before the defaulted budget. `splitChunk` counts `docPrefix + title\n\n` as one head overhead so the BPE join slack stays in one place and a split never overflows with the prefix counted.
- `search.ts`: all 5 enforceTokenBudget + all embedInput call sites pass `activeSpec().docPrefix`; the query embed is `activeSpec().queryPrefix + cleanDenseText(cleanedQuery)`. Carry-over cache keys change with the prefix — fine, a prefix change is an index-identity change (docPrefix ∈ modelKeyFor) → full reindex.
- The shipped granite default has empty prefixes → byte-identical embed input to before (pinned in token-budget.test.ts).
- Tests: new prefix cases in token-budget.test.ts; recording fake embedder (`embedCalls`/`embedBatchCalls`) in test-harness/scenario.ts drives src/model-prefix.test.ts asserting the query starts with 'query: ' and indexed chunk inputs with 'passage: '. All other callers (bench/e2e) pass ACTIVE_MODEL_SPEC.docPrefix.
