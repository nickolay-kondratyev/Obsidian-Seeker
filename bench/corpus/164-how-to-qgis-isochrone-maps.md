# How To: Build Transit Walkshed Isochrone Maps in QGIS

Quick reference for producing walkshed/isochrone maps showing transit accessibility around a set of stops, using the QGIS Network Analysis toolbox and a GTFS-derived street network. Written after redoing this three times and forgetting the plugin settings each time. These are the settings and gotchas I keep losing between projects, so this note exists mostly to save future-me an afternoon of trial and error.

## Building the Isochrones

Start with a clean OSM street network extracted for the study area — I use the QuickOSM plugin, filtering to `highway=*` and excluding motorways, since pedestrians obviously don't walk along freeway shoulders. Save this as its own layer before doing anything else, because the next step edits topology in place and you do not want to redo the extraction if something goes wrong. Run the network's built-in topology check under Vector > Analysis Tools, and fix any dangling nodes it flags; a street network with broken connectivity will silently produce isochrones that are too small in places where a road segment isn't actually snapped to its neighbor, and this is the single most common source of bad-looking output.

Next, load the transit stop points you want to analyze. For a corridor study these usually come straight out of the GTFS `stops.txt` file, filtered to the routes in scope — see [[154-how-to-code-gtfs-data]] for the extraction script I use to pull just the stops served by a given route pattern. Import them as a point layer and confirm the CRS matches your street network; mismatched CRS is the second most common failure mode and QGIS will not always warn you loudly enough about it, especially if both layers happen to look roughly aligned on screen at first glance.

With both layers ready, open the Service Area (from Layer) tool in the Network Analysis toolbox. Set the street network as the input network layer, the stop points as the start points, and define your travel cost as distance in meters rather than time, since walking speed assumptions add a variable I'd rather control separately in a later step. A 400-meter service area is the standard quarter-mile walkshed; I typically run three passes at 400m, 800m, and 1200m to show the falloff in accessibility, since a single ring understates how steeply usability drops off past the quarter mile in most of the corridors I've studied. Each pass produces a set of line features tracing the reachable street segments — this is the raw isochrone skeleton before it becomes a filled polygon.

The line output needs converting to a polygon before it's usable as a shaded accessibility layer. I do this with a concave hull around the reachable network lines rather than a simple buffer, because a straight buffer around stop points ignores the street network entirely and will happily show accessibility across features pedestrians can't actually cross, like a rail yard or a limited-access highway median. Under Vector > Geometry Tools, run Concave Hull on the service area line output with the threshold set fairly tight — around 0.3 in QGIS's parameter, though this needs eyeballing against the actual street pattern, since too loose a threshold balloons the polygon out past where anyone would realistically walk and too tight a threshold leaves gaps at network intersections. Repeat this per travel-cost ring so you end up with three nested polygons per stop.

Once the polygons exist, dissolve overlapping walksheds from adjacent stops using Vector > Geoprocessing Tools > Dissolve, grouped by the travel-cost band rather than by stop, so overlapping 400m rings from two nearby stops merge into one continuous shaded area instead of showing duplicate overlapping shapes. This is the step that turns a scatter of individual stop walksheds into a single corridor-level accessibility picture, which is what actually goes into the thesis figures rather than a busy mess of overlapping polygons that's unreadable at print scale.

For symbology, I use three sequential fill colors at decreasing opacity for the 400/800/1200m rings, laid under a base map with stop points on top as a separate point layer so the eye can still find the actual stops. Export at 300 DPI for print figures using Layout Manager rather than a raw canvas screenshot, which loses resolution and looks noticeably worse in the printed thesis draft. One habit that's saved me real time: save the whole workflow as a QGIS model in the Graphical Modeler once it's dialed in for one corridor, since rerunning it for the second and third corridors becomes a single click instead of redoing eight manual steps and inevitably fat-fingering a threshold value differently each time.

## Common Failure Mode

The one I hit repeatedly: forgetting to reproject the street network into a projected CRS (not WGS84) before running Service Area. This silently produces isochrones measured in degrees instead of meters and looks catastrophically wrong on the map — rings either enormous or invisible depending on which way the units error, with no warning dialog to catch it. Always check the CRS badge in the bottom-right corner before running the tool; it takes two seconds and has saved me from redoing an entire corridor's output more than once.
